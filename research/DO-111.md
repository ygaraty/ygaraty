## Question

DO-110 found headless Chrome on Vast containers running WebGPU on SwiftShader (CPU): Chrome's GPU process fails `vkCreateInstance` with -7 (extension not present), although `vulkaninfo` and the native Node + Dawn worker use the NVIDIA GPU. Which configuration gives Chrome the GPU?

## Gate (frozen 2026-11-25, before renting; budget about $0.15, teardown 45 min)

Passes if some configuration, on the same container:

1. a probe page's `navigator.gpu.requestAdapter()` reports the NVIDIA adapter (vendor nvidia, not swiftshader); and
2. S5-Nano (one worker, public v2 bundle) decodes in that headless Chrome at least 0.8× the native Node + Dawn worker's tok/s on the same GPU (512-token answer, greedy, steady rate after the first 64 tokens).

Configurations, in order, stopping at the first that passes 1: `chrome://gpu` and `vulkaninfo` instance extensions as diagnostics; A) current flags (`headless.sh`, baseline); B) Google's documented headless set with `--disable-vulkan-surface`; C) A or B under `xvfb-run` without `--headless`; D) NVIDIA graphics libraries added to the container, then A–C.
