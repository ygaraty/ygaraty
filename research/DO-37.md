## Question

Does the new `convnet_native` adapter preserve the legacy ConvNet's gradients,
Adam state and DiLoCo pseudo-gradients, and consequently its learning trajectory?
The distributed runtime should not need Torch; the comparison process may use it.
Related: [44](044-diloco-convnet-cifar-one-host.md) establishes historical learning,
[45](045-convnet-remote-scaling.md) covers remote/browser execution, and
[DO-30](DO-30.md) tracks the separate inference migration.

## Prediction

Matched float64 calculations should agree within reduction-order tolerance.
Wire-layout conversion and persistent optimizer state are the main migration
risks. Equal seeds alone are insufficient: NumPy and Torch initialization differ.

## Gate

Proposed acceptance criteria, to be frozen before the remote run:

- At the same initial arrays and batches, logits, loss, parameter gradients,
  Adam moments and updated weights satisfy elementwise `atol=1e-9, rtol=1e-7`
  for the first update. All outputs must be finite.
- Over 100 updates and at least two outer rounds with a rebase, weights,
  optimizer moments and round pseudo-gradients satisfy `atol=1e-8, rtol=1e-6`.
  Per-update cross-entropy differs by at most `1e-6`.
- Across seeds 2026, 2027 and 2028, after one identical full-data epoch,
  held-out cross-entropy differs by at most `1e-3` and accuracy by at most
  0.1 percentage point for each seed, on the same fixed held-out split.
- The Ygaraty arm completes with Torch and transformers imports blocked.
  Reference calculations run in a separate process/environment.

Failure of any criterion fails that gate; report each stage separately. Do not
relax thresholds after observing results. Runtime and peak RSS are descriptive
measurements, not a speedup requirement.

## Protocol

1. On an authorized external host, record commit, Python/NumPy/Torch versions,
   BLAS implementation/thread settings and CPU/RAM. Use an existing local CIFAR
   dataset; freeze its hash, split, preprocessing and minibatch order. Host,
   dataset location, spending budget and teardown deadline are TBD; provision
   nothing until those are agreed.
2. Export one canonical initialization per seed, then load the exact same arrays
   into both implementations. Explicitly check the legacy flattened wire layout
   and transposed classifier matrix. Use CPU float64, Adam learning rate 0.001,
   identical beta/epsilon conventions, and batch size 16.
3. Capture forward values and gradients before optimization, including conv,
   pooling and head outputs. Include a separate max-pool tie fixture and batches
   of sizes 1 and 16; record tie-gradient behavior rather than masking differences.
4. Compare 100 local steps, then two DiLoCo rounds of 50 steps with the same
   coordinator-supplied rebase arrays. Preserve private Adam moments and step
   counters across rounds. Compare the returned starting-minus-final weights.
5. Only after numerical gates pass, compare the one-epoch learning trajectories
   for the three seeds. Keep initialization, example order and held-out evaluation
   identical. Save per-step losses, tensor comparison summaries, accuracy,
   measured runtime and peak RSS under `runs/experiments/DO-37/<host>-<timestamp>/`.
6. Verify the runtime arm has no Torch imports or hidden reference fallback.
   Do not interpret synthetic offline layout tests as numerical training evidence.

## Limits

This evaluates the native CPU float64 adapter. It does not validate WebGPU
float32, GPU performance, volunteer recovery, RL trainers or Phi-4 inference.
Historical Torch results cannot be relabeled as results of this migration.
