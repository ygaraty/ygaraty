## Question

Can the shared Qwen WebGPU implementation run Qwen3.8-27B text-only inference
correctly, fit within 8 GiB per contributor, and serve through the coordinator
with three or four contributors? Measure the memory and latency of relay and
direct routes without introducing a separate model execution engine.

Related: [DO-42](DO-42.md) covers S5 geometry reuse;
[DO-47](DO-47.md) covers compiled-plan migration;
[92](092-qwen35-webgpu-four-contributors.md) records Qwen3.5-9B distribution;
[103](103-fast-sessions-rollout-rerun.md) records direct-mode serving.
This experiment covers a different geometry and checkpoint, not a rerun of them.

## Architecture and prerequisites

The [official config](https://huggingface.co/Qwen/Qwen3.8-27B/raw/main/config.json)
inspected on 2026-11-11 identifies `qwen3_5`: 64 layers, hidden width 5120,
FFN width 17408, 24 query/4 KV heads of width 256, and DeltaNet 16 key/48 value
heads of width 128. Every fourth layer uses full attention. Pin this config
and the actual checkpoint revisions before execution; the linked `main` is
reference documentation, not a reproducible input pin.

Implementation required before recommending a run:

- Generalize validated geometry across `qwen35_gguf.py`, Tape compositions,
  TypeScript manifests, shader generation and kernel-cache identities.
- Derive convolution width 10240, attention width 6144, projection shapes,
  buffer strides, cache/scratch sizes, recurrence states and snapshots from
  geometry. Remove the browser's fixed 32-layer bound.
- Verify GGUF tiled/grouped head reordering with the new 3:1 DeltaNet head ratio
  and full attention's six query heads per KV head. Audit gate semantics against
  the pinned reference; do not infer new arithmetic from `output_gate_type` alone.
- Add same-weight reference conversion and admission cases for the larger
  dimensions. Retain S5-nano and Qwen3.5-9B regression coverage.
- Inspect and pin a Q4 GGUF whose actual tensor types are supported by our
  packed decoders, plus config, tokenizer and chat template. A file labelled
  Q4 or UD-Q4 is not itself evidence of compatibility. Quantizer revision,
  file hashes and GGUF conversion conventions are required evidence.
- Add the model record, installer/catalog entries, Spaces prefix and immutable
  memory-balanced 3/4-worker bundles. Verify the text-only thinking-off template
  matches the pinned tokenizer; vision and learned MTP are outside this scope.

## Prediction

The common layer structure should permit kernel reuse with parameterized
geometry. Four 8 GiB workers are the initial feasibility target, followed by
three. These are hypotheses, not admission guarantees. Direct links may reduce
handoff latency, while three workers may avoid one boundary; GPU speed, placement
and context memory can outweigh either effect. No throughput claim is presumed.

## Gate

Proposed gates to approve and freeze before execution:

1. **Primitive and layer parity:** compare both layer types and state updates
   against a reference using the identical quantized weights. Require finite
   outputs and elementwise `atol=rtol=1e-3` for hidden outputs and states in the
   f32 diagnostic arm. Report maximum errors and cosine similarity as well.
2. **Generation parity:** replay fixed token IDs with a reference that models
   the same cache/wire precision and partition rounding. Require identical
   greedy tokens for up to 128 output tokens, with per-step maximum logit error
   at most `2e-3 * max(1, max(abs(reference_logits)))`. Record top-two margins;
   mismatches fail the gate rather than receiving an automatic near-tie waiver.
   Do not compare a bf16 source model as if it used the same Q4 weights.
3. **Memory:** on actual 8 GiB devices, cold load, admission, longest prefill and
   decode finish without allocation failure/device loss. Peak tracked buffers
   stay within 8 GiB per contributor. Separately record loading peaks, host RSS,
   browser/driver GPU usage and maximum single-buffer allocations. A catalog
   budget or a successful run on a larger GPU is not proof of 8 GiB feasibility.
4. **Transport and lifecycle:** relay and direct give identical output tokens
   for matched physical assignments. Direct links are open at generation start;
   save candidate types, RTT and bytes. Fallback is labelled separately and does
   not count as a successful direct timing run. Three-turn chat, cancellation,
   slot reuse and contributor replacement complete or fail explicitly within a
   predeclared timeout. No duplicate or missing tokens or indefinitely hung turn.
5. **Regression:** existing S5-nano and Qwen3.5-9B cases preserve their prior
   kernel traces and numerical results after geometry generalization.
6. **Performance:** report cold load, warm TTFT, median/p95 inter-token latency,
   aggregate tokens/s, per-stage compute and transfer bytes. Latency is
   descriptive; do not require a speedup for correctness/feasibility to pass.

## Protocol

On an authorized GPU host, start with a linear and a full-attention layer,
then a contiguous mixed block and a full-model reference check. Use chunked
prefill and single-token decode with reset/replay and two independent slots.
Use optional Torch/transformers only for verification, not serving.

Begin with four physically separate contributors, then three, using contiguous
memory-balanced ranges from actual tensor sizes. Exact boundaries are TBD until
GGUF inspection; do not freeze equal layer counts without pricing endpoints,
KV state and recurrent state. Fix capacity 4096, chunk 64, f16 cache/wire and one
conversation for serving; use f32 cache/wire only as a diagnostic comparison.
Disable speculative decoding and freeze the matrix-kernel policy.

Freeze short Portuguese/English/code prompts as token arrays, plus 1024- and
3968-token prefills with at most 128 generated tokens. Respect EOS and the
4096-token total capacity. Keep early stops for correctness; choose timing
inputs with at least 32 decoded tokens before looking at candidate latency.

For each worker count, warm once per route and collect five paired relay/direct
runs, alternating order with identical devices and assignments. Compare routes
within a worker-count cell first. A three-versus-four-worker comparison changes
resource count: report the removed device, layer assignments and cost alongside
latency. Use separate correctness/snapshot and timing runs.

Record under `runs/experiments/DO-52/<host>-<timestamp>/`: frozen gate, source and
model revisions/hashes, input IDs, compiled plans/bundles, reference procedure,
GPU/browser/driver inventory, device/network placement, logits/tokens/states,
allocation traces, raw timing samples, route counters, failures and costs.

**TBD before execution:** compatible quantization and pins, candidate SHA,
reference/harness commands, partition boundaries, hardware/network inventory,
rental budget and teardown deadline. No download, deployment, model workload,
browser contributor or remote job is authorized on the simulation workstation.
Keep this open until implementation and authorized-host prerequisites are ready.
