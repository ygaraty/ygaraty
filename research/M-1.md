## Question

Can we reach a target held-out quality more efficiently by adding model depth only after useful learning, or by replacing expensive correction signals with compact local rules?

M-1 holds two related ideas with separate comparisons. Neither idea's success establishes the other. Keep results per idea and do not mark the whole experiment executed while an agreed comparison remains pending.

Origin: [shared discussion of learning as a sequence of approximations](https://chatgpt.com/share/6ae76503-9c68-83eb-b070-1085f2b3bbb4), continued on 2026-11-01. The user requested the Modeling Experiment track.

## Ideas and order

| Label | Idea | What changes | First comparison |
|---|---|---|---|
| A — original | Compact local corrections | How a layer receives its update signal | True backpropagated correction versus a linear predictor, then a symbolic rule, then a meta-learned rule (VSML arm, added 2026-11-03), at fixed architecture |
| B — proposed first test | Learn before growing | When model capacity is introduced | Output head first, then one hidden block, versus that same final architecture trained from scratch |

Run B's smallest comparison first because it isolates the user's new idea with ordinary gradients. A remains an independent line of inquiry. Combining growth and approximate corrections is deferred until each has its own evidence.

### B: train the output layer, then grow toward the input

Working interpretation: begin with an output head on raw inputs or a fixed, explicitly declared feature map. There is no untrained deep feature extractor in this first arm. Add a hidden block upstream of the trained model after the current stage has demonstrated useful learning. If the intended idea is instead to unfreeze an already-existing network from output toward input, record that as a different protocol before running.

With fixed features u, output head g, and compatible hidden blocks B1 and B2:

```text
Stage 0: u -> g -> prediction
Stage 1: u -> B1 -> g -> prediction
Stage 2: u -> B2 -> B1 -> g -> prediction
```

Each added block is the new earliest trainable block. Prefer a residual block initialized to preserve the previous input/output mapping, so insertion does not erase the learned predictor. Verify preservation numerically on the authorized host before continuing; constrain dimensions and activations accordingly.

Define "learned something" using a development split: improvement exceeding a predeclared threshold relative to that stage's entry checkpoint (for stage 0, also compare a constant/class-prior predictor). Proposed growth condition: that improvement has occurred, progress has plateaued for a fixed patience window, and the target quality is still unmet. Stop if the target is reached. If a stage reaches its budget without qualifying improvement, record a stalled stage; do not silently add depth anyway. A problem needing nonlinear features may fail this initial gate, which is a limitation of the strict rule itself.

For the first comparison, fine-tune all existing weights after insertion using ordinary backpropagation. Freezing the already-trained stack while learning only the new block is a separately labeled ablation. Freezing weights does not remove the need to propagate derivatives through that stack to train an upstream block.

### A: approximate the correction signal

For one use of a dense layer z = Wa, its weight gradient is delta times a transpose, where delta is the loss derivative with respect to z. Predict this correction vector from local activations and compact history instead of predicting every weight update. Minibatches and shared-weight uses require summing contributions. Hold architecture fixed while testing this idea.

## Prediction

A compact rule may preserve useful learning while reducing dependency on downstream backward computation. In distributed execution, avoiding that dependency may matter more than arithmetic savings. This is a hypothesis, not a demonstrated speedup. Local information may be insufficient as downstream weights change.

Progressive growth may spend less early computation on unnecessary depth while preserving what the smaller model learned. It could also delay useful feature learning or trap the model in a poor representation. No improvement is assumed.

#### Architecture and insertion

Keep the existing output head and add the convolutional blocks from output toward input:

| Stage | Trainable model | Input supplied to the trainable suffix | Trainable parameters |
|---|---|---|---:|
| 0 | Average pooling + Linear(128,10) | Fixed 128-channel, 8x8 features | 1,290 |
| 1 | Conv(64,128)-ReLU + head | Fixed 64-channel, 8x8 features | 75,146 |
| 2 | Conv(32,64)-ReLU-MaxPool2 + stage 1 | Fixed 32-channel, 16x16 features | 93,642 |
| 3 | Conv(3,32)-ReLU-MaxPool2 + stage 2 | Normalized RGB, 32x32 | 94,538 |

Define the fixed features explicitly, without a random or pretrained CNN. Normalize RGB
to [-1,1] as the current runner does, apply ReLU, apply one MaxPool2 for the 16x16
prefix or two for the 8x8 prefix, and repeat channels so output channel j copies
RGB channel j modulo 3. These are fixed operations with no learned parameters.
The stage-0 classifier therefore has only three distinct pooled features; repeating
channels does not add information. Failure of this weak initial learner to pass the
growth gate is a valid failure of the strict B protocol, not permission to grow anyway.

Initialize each newly inserted convolution with zero biases and zero kernels except
the center coefficient mapping output channel j to input channel j modulo 3, set to one.
Before training that convolution, it reproduces the removed fixed channel-copy prefix;
ReLU and pooling match the previous prefix. This construction should preserve logits
while leaving the final stage exactly the existing SmallConvNet architecture. This is
an analytical proposal, not numerically verified. The authorized host must check every
insertion against its pre-insertion logits (proposed float64 max absolute error 1e-10)
and abort on failure. Do not substitute arbitrary random layers.

All previously introduced weights remain trainable. The first authorized correctness
check covers stage 0 to 1; only then test all three transitions and the learning campaign.
Stage 1 already contains most parameters, so large early communication savings are not assumed.

### Independent follow-up: A, fixed architecture

1. Select a small supervised network and an existing dataset on an authorized workload-training workstation. Exact model, dataset, split hashes, hardware, and commands: TBD. This simulation-only machine must not perform numerical workload training.
2. Replace the correction signal at one hidden layer. Compare ordinary backpropagation, a linear correction predictor, and a compact symbolic rule. Specify each rule's inputs, state size, fitting method, teacher access, and refresh schedule before running; keep the remaining layers' learning procedure matched.
3. Use matched initializations, data orders, and training budgets. Separate predictor fitting from evaluation trajectories, including unseen initializations and later training phases. Record instability, missed quality targets, and failures.
4. Measure complete trajectories and all auxiliary costs. A workstation learning screen establishes quality and local runtime only. Any later distributed measurement needs an explicit topology and authorized host; simulation can estimate communication effects but cannot establish numerical quality or real-system speed.

5. **VSML arm (added 2026-11-03).** Kirsch & Schmidhuber, [*Meta Learning Backpropagation And Improving It*](https://arxiv.org/abs/2012.14905) (NeurIPS 2021), replace every weight with a tiny LSTM whose parameters (about 2,400) are shared across the whole network. Weights live in the LSTMs' states, and learning emerges from forward and backward messages, with no explicit gradient. Meta-trained by backpropagation or evolution strategies, it imitates backprop on MNIST (about 87–90% against gradient descent's higher accuracy), transfers to Fashion-MNIST, KMNIST and EMNIST, and learns faster than Adam early, before gradient descent overtakes it (beyond its roughly 500-example meta-training horizon).
   - **Why it fits A:** the rule is one shared, tiny set of parameters, identical on every contributor, so the only state to synchronize besides activations and errors is a few thousand numbers. Its early-training advantage is the regime this project works in.
   - **What it does not do:** it still needs a backward error message per layer, so it removes no hop. Compute is O(W·N²) for W weights and state size N, so it is for A's small networks only, not the translator.
   - **Arm:** replace the chosen hidden layer's update with a VSML sub-network (state size N = 8–16), meta-trained on a separate task family (for example MNIST variants) and tested on A's task with unseen initializations. Charge meta-training separately from the evaluation trajectories, as A requires for predictor fitting. Compare with ordinary backpropagation and with A's linear predictor at equal examples seen.
   - **Meta-training by evolution strategies** is the step that could use the pool: see [WS-7](WS-7.md).

Related research: [synthetic gradients](https://proceedings.mlr.press/v70/jaderberg17a.html), [VSML](https://arxiv.org/abs/2012.14905), [fast weight programmers](https://proceedings.mlr.press/v139/schlag21a.html), and [test-time training](https://arxiv.org/abs/2407.04620).

## Limits

The initial comparisons concern one correction interface or one added block. Success would not establish a general replacement for backpropagation, convergence guarantees, or transfer to Transformer-scale workloads. The exact baseline's gradient can depend on downstream state absent from local observations. A developmental plateau does not prove that depth is the missing ingredient. Progressive growth changes the optimization path; its comparison measures the complete training strategy, not depth alone.
