## Question

Experiment 82's GPUs peaked at 7.4 GB of 8 GB, with prompts of up to 3,968 tokens and one session at a time.

Phi-4's KV cache is about 0.2 MB per token in bf16: 40 layers, 10 KV heads, head size 128, keys and values. Split over 2 owners, that is about 0.1 MB per token per owner:
- 400 MB per owner at 3,968 tokens;
- 1.6 GB at Phi-4's 16,384-token context.

So 8 GB GPUs cannot hold long prompts or several sessions. BloomBee (arXiv 2604.21072) offloads part of the cache to CPU memory and reports 1.82× more throughput per GPU dollar.

**With the KV cache partly in CPU memory, can experiment 82's 8 GB pair serve a 16,384-token prompt, or 4 concurrent 3,968-token sessions, with the reference's tokens, and how much does each decoded token slow down?**

## Prediction

- **Capacity:** a 16,384-token prompt fits with only the last 2,048 positions per layer on the GPU and the rest in pinned CPU memory. Four 3,968-token sessions fit likewise.
- **Cost per token:** each decode step reads the offloaded keys and values over PCIe, about 1.4 GB per owner at 16,384 tokens. At about 10 GB/s that adds 0.15–0.25 s per token per owner. Overlapping the reads with the 4-bit unpacking hides part of it. Inter-token latency rises from 1.35 s to about 1.5–1.8 s at 16,384 tokens; at 3,968 tokens the rise is under 10%.
- **Tokens:** equal to the GPU-resident run, bit for bit (offloading moves data, it does not change arithmetic), where the GPU-resident run fits.

## Protocol

1. **Code:**
   - a two-tier KV store in `phi4_kernels`: the last W positions per layer on the GPU, older ones in pinned CPU memory;
   - attention that streams the CPU part in blocks and merges with the GPU part (log-sum-exp merge);
   - a flag `--kv-gpu-window W` (0 means all on the GPU, today's behaviour).
2. **Tests (tiny model, float64):**
   - attention with any window equals the all-GPU attention to 1e-12;
   - cached decode equals the uncached forward.
3. **Arms on experiment 82's pair:**
   - W = all (today) at 3,968 tokens;
   - W = 2,048 at 3,968 and at 16,384 tokens;
   - 4 concurrent 3,968-token sessions at W = 1,024, if DO-21's session interleaving is in place, otherwise serial.
4. **Runs:** 3 interleaved warm sessions per arm, 32 new tokens.
