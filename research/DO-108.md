## Question

The v2 bundles raise the context from 4,096 to 16,384 tokens and the output limit from 256 to 4,096, with the same weights. S5-Nano passed on this workstation's Radeon 680M (two workers: a 4,096-token answer with every counted number correct at a flat 14.0–14.5 tok/s, and an 11,318-token prompt that found a fact in its first line). Does the 27B do the same, past 4,096 positions, with its own head geometry (6 query heads per KV head)?

## Gate (frozen 2026-11-25, before renting; budget $2, teardown 2 h)

On one RTX 3090, `serve --model qwen3.8-27b --num-workers 1` from the published v2 bundle, greedy (temperature 0):

1. **Long answer:** "Count from 1000 to 3000, one number per line …" runs to exactly 4,096 completion tokens with `finish_reason: length`, and every complete number is correct. If the model stops on its own before the limit, the answer is still checked for correct numbers, and the limit is checked with a second prompt; the gate needs one answer of 4,096 tokens ending in `length`.
2. **Long prompt:** a ~11,300-token prompt with "the secret code word is PELICAN-42" in its first line, asking for the code word, answers PELICAN-42.
3. **No slowdown or failure:** no failed request; decode speed in the last 256 tokens at least 0.8× the first 256.

Passes if all three hold. A two-worker run on the same GPU (both stages in one machine) repeats 1 and 3 if time and memory allow; it is reported, not gated.

## Protocol

DO-62's host recipe (`runs/experiments/DO-62/tools/host.sh setup`: Vulkan, Node 26.8.2 + webgpu@0.6.2, this tree as `src.tar.gz`), then `serve --model qwen3.8-27b --num-workers 1 --route relay` on 127.0.0.1, one native contributor (`native_contributor.mjs LINK --webgpu-module …`), then the long-answer and long-prompt clients (`runs/experiments/DO-108/tools/`). Speeds per 256 tokens are recorded.

## Limits

One host, one GPU type, one worker per model; greedy decoding; the counting task checks positions and limits, not answer quality. Reading prompts is slow on the 27B (11K tokens in about 230 s), which a prefill profile should explain. After a failed request the worker kept reading the prompt.
