## Question

The tied embedding and output layer is the model's largest single matrix, about 8.2M of 30.3M parameters (vocabulary × 512). ALBERT (Lan et al. 2019) factorizes it into V×r and r×H, with r much smaller than H. Sainath et al. (ICASSP 2013) factorized only the large output layer of speech DNNs with no loss in accuracy.

In Ygaraty the vocabulary is split across slice owners, and every update sends hidden states to them and gets partials back. If the slices worked in r dimensions instead of 512, that traffic would shrink about 512/r times, and each slice owner would hold about r/512 of today's state.

**At 32,768 pairs, how much held-out loss does a rank-r factorized vocabulary layer cost against full rank, at r = 64, 128 and 256?**

This is the learning half only. Whether the slice traffic actually shrinks is a separate distributed question, worth asking only if this passes.

## Prediction

- **Loss:** r = 256 within 0.02 of full rank; r = 128 within 0.05; r = 64 loses about 0.1. ALBERT reports a small cost at E = 128 for a 30k vocabulary.
- **Training from scratch against factorizing later:** factorizing after a full-rank warm-up (Pufferfish, MLSys 2021) loses less than training factorized from step 0.
- **Parameters:** at r = 128 the layer falls from about 8.2M to about 2.1M.

## Protocol

1. **Code:** `--factor-vocab r` in `batch_learning`. The embedding becomes A (V×r) times B (r×512), tied: the input is A[token]·B, and the logits are (h·Bᵀ)·Aᵀ. Initialize so that A·B has the same scale as today's embedding. Add `--factor-vocab-at N` for the warm-up arm: train full rank, then at N pairs replace E with its truncated SVD, split as A = UΣ^½ and B = Σ^½Vᵀ, and continue.
2. **Arms:**

   | Arm | Vocabulary layer |
   |---|---|
   | F | full rank (experiment 67's Adam arm, WS-3; reuse it if run on the same commit) |
   | R64, R128, R256 | factorized from step 0 |
   | W128 | full rank to 8,192 pairs, then SVD to r = 128 |

3. **Runs:** 2 seeds (2026, 2027), 32,768 pairs, held-out loss every 4,096 pairs. About 1 hour per arm and seed on CPU, or a cheap GPU machine.
4. **Prepare on the workstation:**
   - a unit test that `--factor-vocab 512` with A = I-padded reproduces the full-rank logits to float64 tolerance;
   - a test that the SVD split at `--factor-vocab-at` leaves the loss unchanged when r equals the full rank.

## Trigger on the workstation

```bash
git pull && pip install -e . && python -m unittest tests.test_factor_vocab
export YGARATY_DATASET_URL=sqlite:///$PWD/runs/datasets/opus100-en-pt/opus100-en-pt.sqlite
COMMON="--embedding 512 --hidden 2048 --heads 8 --layers 3 --version 1m-seed2026 --batch 64 --length-window 64 --batch-tokens 3072 --pairs 32768 --eval-every 4096 --optimizer adam --learning-rate 0.0005"
for seed in 2026 2027; do
  ygaraty experiment batch_learning $COMMON --seed $seed --output runs/experiments/M-3/F-$seed
  for r in 64 128 256; do
    ygaraty experiment batch_learning $COMMON --seed $seed --factor-vocab $r --output runs/experiments/M-3/R$r-$seed
  done
  ygaraty experiment batch_learning $COMMON --seed $seed --factor-vocab 128 --factor-vocab-at 8192 --output runs/experiments/M-3/W128-$seed
done
```

`--factor-vocab` and `--factor-vocab-at` are what has to be built. Flags in `COMMON` follow WS-3's trigger; check them against the current `batch_learning --help`.
