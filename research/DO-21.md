## Question

Compare serial sessions, interleaved stage execution and stage batching under concurrency. Needs DO-18 first; reuse one pinned backend across arms.

Related: [Phi-4 GPU baseline](081-phi4-two-h100-pipeline.md),
[inference plan](../../inference.md).

## Prediction

Independent sessions can fill pipeline idle periods, but batching and memory pressure can worsen tail latency.

## Gate

Proposed: at least 20% more requests completed within a predeclared TTFT/inter-token SLO versus unbatched execution, with no correctness failures. Actual SLO and workload mix TBD before running.

All proposed gates require confirmation and freezing before execution.

## Protocol

Sweep concurrency 1/2/4/8 with fixed prompt/output distributions and seeded arrivals. Measure queueing-inclusive TTFT, inter-token p95, useful output tokens/s, completion rate, KV memory and per-session fairness. Include both saturation and low offered load. Exclude timed-out requests from successful throughput but retain their resource costs. Validate isolation, cancellation and cleanup.

All deciding runs take place on the authorized dev server or remote test machines,
not this simulation-only workstation. This entry authorizes planning only, not
provisioning. Host inventory, budget (if rented), teardown deadline, checkpoint
hashes and exact runner commands are TBD. No services or workloads were started.

Use pinned prompts of 128/1024/3968 tokens and up to 128 generated tokens for
single-session comparisons unless the frozen protocol explicitly changes them.
Record EOS and actual lengths. Start with at least five warm measured repeats,
report variability and repeat borderline outcomes; do not treat a handful of
session summaries as a reliable request-tail estimate for load tests. Use
monotonic clocks, synchronized GPU timing where needed and explicit timing
boundaries. Save commands, source revision, input hashes and raw traces under
`runs/experiments/DO-21/<host>-<timestamp>/`. Commit the driver and analysis code.
