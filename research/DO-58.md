## Question

DO-56 and DO-57 make long context fit by losing some quality. The training side of Ygaraty already shows an exact alternative: the output layer was cut into vocabulary slices, each owner computed its part, and only a few softmax statistics crossed the network (experiment 32).

Attention splits the same way along positions. Each memory contributor holds the K and V of a range of positions for a stage's full-attention layers. For each token it receives the query (4 heads × 256 values, 2 KiB in fp16), and returns its partial result: the maximum score, the sum of exponentials and the weighted sum of values per head (about 2 KiB). The stage merges the partials exactly, as split-K decoding does (FlashDecoding), up to the order of floating-point sums.

Context then grows with the number of contributors, the attention work is spread over them, and the stage's own memory stays fixed.

**With older KV positions held by memory contributors, does Qwen3.5 keep the single-GPU tokens at contexts several times what one 4 GB stage holds, and what does it add to time per token?**

## Prediction

- **Tokens:** identical to the single-stage run except at near-ties, since the merge reorders sums.
- **Context:** each memory contributor with about 3.5 GB free holds about 200k positions of one stage's 4 full-attention layers in fp16; two per stage reach 400k+.
- **Time per token:** each full-attention layer adds one parallel round trip to its memory contributors: 4 per stage per token, about 2–3 ms each over direct links (experiment 97), so +20–30 ms on 83 ms. With the four layers' queries pipelined across tokens it cannot shrink below one round trip per layer, since layer 7's query depends on layer 3's output.
- **Compute:** about the same total as one GPU holding everything; the stage itself does less at long context.

## Gate

TBD, to be frozen before the rented run. Proposed:
- **Exactness (workstation, S5-nano, required):** sliced attention equals single-device attention within float32 reassociation (relative 1e-6), and 128 greedy tokens are identical at 4k and 16k with 1 and 2 memory contributors.
- **Counts as useful:** on experiment 97's hosts plus memory contributors, a context at least **4×** what one 4 GB stage holds alone, with tokens identical (near-ties excused) and time per token at most **+35%** against experiment 97's 83 ms.
- **Report also:** time per token by context and contributor count; bytes per token per memory contributor; what a lost memory contributor costs (its positions must be rebuilt by re-prefill or from a copy).

## Protocol

1. **Code:**
   - a `kv-slice` contributor role holding positions [a, b) of a stage's full-attention layers, receiving K/V as they are appended (the stage forwards new positions in batches), and answering partial attention for a query;
   - the stage's merge of partials (max, sum-exp, weighted sum) per head, and its own recent positions computed locally;
   - placement: positions beyond the stage's own budget go to slices in order.
2. **Workstation (S5-nano, local headless contributors):** the exactness tests (`tests.test_qwen35_kv_slices`) and one 16k session with 2 slices.
3. **Rented:** experiment 97's two RTX 3060 stages plus 2 memory contributors (any 4–8 GB GPUs), contexts 16k, 64k, 128k, 256k; arms 0, 1, 2 memory contributors per stage; 3 repeats.
4. **Stage 2 (only if useful):** query-aware page selection (ask only the slices whose page summaries score highest, Quest-style), which bounds attention work per token at long context but is no longer exact; quality measured with DO-56's harness.

## Cost and limits

- **Cost:** about 3 hours of 4–5 small GPUs and the coordinator, about $2–3. Confirm a budget and teardown deadline before provisioning.
- **Limits:** a memory contributor that leaves loses its positions; long prompts' prefill still costs O(n²) in the full-attention layers, now spread over the slices.
